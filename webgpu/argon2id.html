Argon2id on WebGPU

The same Argon2id fill phase compiled to a WGSL compute shader and to WebAssembly, in one browser and one process, on Anubis's parameters (Argon2id v1.3, m = 19456 KiB, t = 2, p = 1, 32-byte tag). The page does not trust the GPU: before using it, it hashes a few known (challenge, nonce) pairs and compares the full digests against wasm/argon2id_pow.wasm. If they disagree the page reports it and falls back to WebAssembly instead of returning wrong answers faster — the same rule the C engine applies to every GPU hit.

The ~19 MiB working set per hash is the whole design constraint here: concurrency is maxStorageBufferBindingSize / 19456 KiB, and the table below prints both the limit and what was actually used.

One hash is one workgroup of eight invocations: the 1 KiB block function is 8 independent BLAKE2 rounds, then a barrier, then 8 more, so eight lanes share each block fill instead of one lane walking all 38,912 of them. That matters: with a single invocation per hash the 19 MiB fill takes ~8 s per hash on the Intel iGPU and the driver kills the dispatch (VK_ERROR_DEVICE_LOST); with eight it completes and is bit-exact.
