SHA-256 on WebGPU

The same Anubis sha256 proof of work in a WGSL compute shader and in WebAssembly, in one browser and one process. The page does not trust the GPU: before using it, it hashes known (challenge, nonce) pairs and compares the digests against wasm/sha256_pow.wasm. If they disagree — which is the useful diagnostic for the Intel backend — the page reports it and falls back to WebAssembly instead of returning wrong answers faster.

The check covers both nonce byte orders (little-endian when the challenge's last byte is ≥ 0x80, big-endian otherwise, per wasm/sha256_pow.c) and nonzero nonces: nonce 0 is four zero bytes either way, so a check that only used nonce 0 would not notice a reversed nonce encoding at all.
