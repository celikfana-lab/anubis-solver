Ninety seconds to your first solve

You need a C compiler and Python 3.9+. Nothing else — no Node, no CUDA, no config file. 

# build the engine
git clone https://github.com/celikfana-lab/anubis-solver
cd anubis-solver && make -j8

# solve a real challenge and print the page behind it
python3 anubis_solver.py https://anubis.techaro.lol/

That is a full pass-challenge round trip: read the challenge, solve it, submit, receive the auth cookie, fetch the page you asked for. Real output from a local gate looks like solved sha256 difficulty=8 nonce=212 in 1.3 ms, then the page itself. The solver reads the algorithm out of the challenge, so it does not care which one the deployment chose.

What is in the box

Four ways in, all backed by the same C engine.
piecewhat it gives you
libanubis_solver.so the engine: all six algorithms, the search loop, and a reference verifier. ~20 M SHA-256/s on one class of core, 10x faster than the in-page wasm at difficulty 20.
anubis_solver.py Python library, requests-free HTTP client and a CLI. The shortest path to a solved challenge.
betterAnusbis/ an Anubis-compatible gate in one C file: same JSON, same routes, same cookie name. Puts the wall up instead of climbing it.
firefox-extension/ native messaging host, so a real browser solves with the native library rather than the page's wasm.

The two results worth knowing before you read anything else

Anubis ships its own WebAssembly modules, one per algorithm, and they are good. So the interesting question is not "does this work" but "does it beat the thing already in the browser". Measured, in the same process, on the same challenge:

Client-side hashrate. Ratios are from the same run; absolute numbers move ~30% with this laptop's governor. Full tables in Numbers.
kernelthis repoAnubisverdict
SHA-256, wasm 3.0–3.9 M/s1.7–1.9 M/s 1.8–2.1× faster
HashX, compiled from the challenge 2.9–3.2 M/s0.37–0.44 M/s 7–8× faster
Argon2id, whole hash 64.6–74.8 ms67.8–76.0 ms 1.02–1.05× faster
Gate server memory 2.1 MB44–46 MB ~21× less

Argon2id is barely ahead, and saying so is the point: it is memory-hard, both sides do the same 38,912 block fills, and the honest claim is "a tie leaning our way", not "many times faster". The reasoning behind each number, and the flag that used to make one of them twice as slow, is in Numbers.
